# Void Journal

A native macOS app for writing your thoughts down and letting them go. As you write, older
words slowly disappear with a satisfying animation. Nothing is ever saved.

## Product spec (source of truth)

- **Purpose:** a very simple journal where your words vanish as you write.
  Simplicity is a feature. Push back on additions that clutter it.
- **Platform:** macOS desktop only, written in Swift with SwiftUI and AppKit. It should feel as
  native as possible: system fonts, standard menus, a Settings window, native buttons and
  pickers, full screen support, hidden-until-needed window chrome, and respect for
  Reduce Motion.
- **Two themes, each in light and dark mode** (Appearance: System / Light / Dark):
  1. **Dissolve:** letters break apart into particles that drift up and away, sweeping left
     to right. The background is a quiet paper (light) or ink (dark) surface.
  2. **Void:** words rise slightly, soften and fade into violet, over dark (or light lavender)
     purple "void" gradients. The gradients drift slowly; this can be turned off in Settings.
- **Pacing:** releasing words speeds up when the user types fast and slows down when they
  slow down. The user must never feel the disappearing can't keep up, and must never feel
  chased by it.
- **Always keep something visible:** the current sentence stays on screen, bounded between
  about 45 characters and about one and a half lines. The text never fully disappears on its own.
  (⌘↩ "Let Everything Go" releases everything on purpose.)
- **Kept text visibly starts letting go, more strongly the further back it is:** the last
  two words are never touched. From the third word back, the effect builds up over about six
  words on an ease-in curve (`aging^1.4`), up to about 65 % dimmer for the oldest words.
  In Dissolve, a few particles keep drifting off older
  letters like smoke; this one is liked, so keep it. In Void, older words tint
  violet and stay in place, with no lift, pulsing or other time-based change. The contrast must stay steady when the
  user pauses and resumes. The strength of each glyph eases toward its target (τ ≈ 0.9 s), so
  new words never make older ones jump. The full release animation continues from this aged
  state without a jump.
- **Text size:** Small 18 pt / Medium 22 pt / Large 28 pt (default, `TextSize.standard`) / Extra Large 34 pt.
  It can be set in Settings or with View ▸ Bigger (⌘+), Smaller (⌘−) and Default Size (⌘0).
  The maximum column width scales with the size (680 pt at Medium) to keep a comfortable
  line length. The intro always uses its own 30 pt size.
- **Writing only moves forward:** you can backspace through text that hasn't started
  fading yet. Arrow keys and other navigation are ignored. Paste works.
- **Intro on first launch:** it explains the concept by demonstrating it. Sentences type
  themselves and then let go with the current theme's animation. It ends with a card that
  recommends full screen for full immersion (Enter Full Screen / Not Now) and lets the user
  pick a theme. Help ▸ Show Introduction replays it.
- **It should feel calm and satisfying** throughout: long, eased fades, a soft glide when
  lines move up, a hidden cursor while typing, and traffic lights that fade while writing.

## Building (no Xcode required)

The project is a Swift package. A script assembles a real `.app` bundle from it.

```bash
make run           # build release .app into ./build and open it
make debug         # debug build of the .app
make install       # copy to /Applications
make reset-intro   # show the intro again on next launch
swift build        # just compile
make format        # format all Swift code in place (swift-format, bundled with the toolchain)
make lint          # check formatting/style; must pass with no warnings
```

- Code style is enforced by `swift format` using `.swift-format`. That config is the
  default configuration with 4-space indentation and a 120-character line length. Run
  `make format` after editing Swift files and keep `make lint` clean.

- The machine has only the Command Line Tools (no Xcode). In the macOS 27 SDK, SwiftUI's
  `@State` (and `@Observable`, `#Preview`) are **macros whose plugins ship only with Xcode**,
  so **do not use `@State`/`@Observable`**. Use `ObservableObject` + `@StateObject`/
  `@Published`, and `@AppStorage` (both still work). Metal shader files can't be compiled
  either, so effects are drawn with SwiftUI `Canvas`.
- `Resources/AppIcon.icns` is generated by `scripts/make-icon.swift` if it's missing. To
  change the icon, edit that script, delete the `.icns`, and rebuild. The icon is a dark void
  inside a thick white-to-lavender gradient ring on a bright violet gradient. Icon feedback
  so far: it must look punchy and read well at Dock size; no fades, no particle dissolves,
  and no crescent (it reads as a sleep tracker).
- Visual check without screen recording: `.build/debug/VoidJournal --snapshots <dir>`
  renders frames of every theme and mode to PNGs (`Sources/VoidJournal/Debug/Snapshots.swift`).

## Architecture

```
Sources/VoidJournal/
  App/        VoidJournalApp (scenes + menus), AppModel/AppDelegate, Preferences (enums + keys)
  Engine/     JournalEngine (text model, wrapping, pacing), GlyphCache (glyph outlines + particle samples)
  Rendering/  JournalRenderer (draws a frame into a Canvas), Palette
  Views/      JournalView (root), JournalCanvas, InputCaptureView, Backgrounds, IntroView, SettingsView
  Debug/      Snapshots (offscreen rendering)
```

- **JournalEngine** holds an append-only array of `Glyph`s. Everything before `frontier` has
  been released (`releasedAt`) and is animating out. `tick(now:)` runs once per frame and
  moves the frontier toward `targetFrontier()`. The speed is
  `max(3 chars/s, typingRate × 1.1, backlog × 0.5)`, and `typingRate` is an exponentially
  decaying keystroke counter (τ = 2 s). Spaces are released for free, so release moves word
  by word.
- **Layout** is a hand-written greedy word wrap over per-glyph advances. A line is only
  removed from the front once every glyph on it has finished fading. Because wrapping
  restarts at line starts, the remaining lines never reflow. `droppedLines` and the eased
  `displayLine` keep the vertical glide continuous.
- **Aging:** `JournalEngine.updateAging(dt:)` sets each glyph's `aging` (0…1) from its word
  distance to the end of the text (the last 2 words are 0, then it ramps over 6 words). It
  never decreases for released glyphs. `JournalRenderer.shed(...)` draws the looping smoke particles for kept glyphs in Dissolve. Because kept
  text keeps moving, the canvas runs at full frame rate whenever unreleased text is on screen.
- **Rendering** fills cached CoreText glyph outlines, so there's no per-frame text layout.
  Particles are batched into 4 opacity buckets, one fill per bucket. Color emoji, which have
  no outline, fall back to `Text`.
- **Redraw policy:** `JournalCanvas` runs at full frame rate while `engine.isAnimating`,
  which includes any unreleased text being on screen. When the page is empty it drops to
  2 Hz to blink the caret. The Void gradients
  animate at 30 fps and pause when turned off or when Reduce Motion is on.
- **Input:** `InputCaptureView` is a transparent NSView implementing `NSTextInputClient`, so
  dead keys, accents (e.g. Czech ř, ů) and IMEs work. `firstRect` places the candidate window
  at the caret.
- Preferences live in `UserDefaults` via `@AppStorage` (keys in `PreferenceKey`).
  Journal text is never persisted.
